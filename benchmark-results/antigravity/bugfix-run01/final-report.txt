## Bug Report & Fix Summary

### Bug 1 â€” CSV sync script un-checking marks todos as done

**Cause:** The PUT handler used `Boolean(req.body.completed)`, which coerces any truthy value to `true`. The string `"false"` (read from a CSV) is truthy, so sending `completed: "false"` resulted in `completed: true` â€” the opposite of the intended value.

**Fix (`server.js`):** Replaced the whole PUT handler with strict validation:
- **API-01:** Check `typeof req.body.completed !== 'boolean'` â€” reject with 400 if it's a string, number, null, or anything else non-boolean.
- **API-02:** Added the same digits-only / range check used by DELETE (BigInt comparison), supporting leading zeros.
- **API-03:** Reject non-object bodies (e.g. arrays) with 400.
- **API-04:** All validation runs before any mutation, so a bad request leaves the todo unchanged.
- **API-05:** Valid `completed: true/false` and title updates continue to return 200.

### Bug 2 â€” No feedback when server is down

**Cause:** `toggleStatus()` in `index.html` had no error handling â€” it called `fetchTodos()` unconditionally whether the request succeeded or failed, and showed no error message.

**Fix (`index.html`):**
- Wrapped the `fetch` in a `try/catch` to handle network failures.
- Checked `res.ok`; if false, reads the error message and displays it in a `<span role="alert">` inside the todo's `<li>`.
- On failure, `fetchTodos()` is **not** called, so the UI reverts to the pre-click state (UI-03).
- Each `<li>` now contains an alert span (`id="alert-${item.id}"`) for per-item error display (UI-02).
