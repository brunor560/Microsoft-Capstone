Implementation Summary

The task was completed following all user-interface, API, interface contract, and constraint requirements.

Files Changed:

app/server.js

Updated the PUT /api/todos/:id route to validate the title payload whenever supplied.
Enforced that supplied titles must be strings whose trimmed value is non-empty, returning HTTP 400 for empty, whitespace-only, or non-string titles.
Ensured title validation rejects invalid title updates prior to mutating any state (preserving completed status and leaving all todos intact if validation fails).
Preserved existing behavior for completion-only updates (completed without title) and preserved completion state and ID when updating title only.
Retained HTTP 404 behavior for nonexistent todos and preserved all GET, POST, and DELETE endpoints.

app/public/index.html

Added an "Edit" button to each todo row.
Added data-todo-id="${item.id}" to each todo's <li> element.
Implemented inline editing mode containing an input initialized with the current title, a "Save" button, and a "Cancel" button, all belonging to that todo's list item.
Gave the editing input the accessible name "Edit title" via aria-label="Edit title" and an associated screen-reader label <label for="...">Edit title</label>.
Enabled full keyboard navigation (Tab navigation between input and buttons, Enter to save, Escape to cancel).
Implemented whitespace trimming upon saving and visible error reporting inside an element with role="alert" belonging to the affected todo's list item.
Preserved draft text in the editor and kept the editor open upon empty/whitespace validation errors, non-success HTTP responses, or network errors.
Restored original title and closed the editor without modifying the todo upon clicking "Cancel".
Rendered titles using textContent to ensure literal text rendering and prevent HTML injection or XSS execution.
Preserved existing task addition, delete interactions, and completion toggling by clicking displayed titles when not in edit mode.

app/test.js

Preserved all 9 existing test cases.
Added 7 local API tests covering:
Valid title update and whitespace trimming (PUT /api/todos/:id).
State preservation (preserving completed state and ID when updating title only).
Validation rejection (HTTP 400) for empty strings and whitespace-only titles.
Validation rejection (HTTP 400) for non-string types (number, boolean, null, object, array).
Rejection behavior preventing mutation of completed state when an invalid title is supplied alongside completed.
Completion-only update retention.
Non-existent ID handling (HTTP 404).
