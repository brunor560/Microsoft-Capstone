I added title editing to the todo app, and `npm test` passes all 14 tests. I did not check the editing interface in a browser, so the UI requirements are untested.

**Files changed** (only the three allowed ones):
- `app/server.js`: `PUT /api/todos/:id` now checks a supplied title before changing anything. A title that isn't a string, or is empty or whitespace-only after trimming, returns 400 and leaves all todos unchanged, even if `completed` is also in the request. A valid title is trimmed and saved, and the response is 200 with the updated todo. Completion-only updates and the 404 for an unknown id work as before.
- `app/public/index.html`:
  - **Rendering:** the list is now built with DOM calls and `textContent` instead of `innerHTML`, so titles show as literal text. Each `<li>` has `data-todo-id`.
  - **Edit controls:** each row has Edit, Delete and a clickable title that toggles completion. Edit opens an input with `aria-label="Edit title"` plus Save and Cancel. Enter saves and Escape cancels, and focus moves to the input and back to Edit.
  - **Save and errors:** an empty title or a failed save (non-OK response or network error) shows a `role="alert"` message inside that row. The editor stays open with the draft kept, and the draft is never shown as saved. A successful save closes the editor and shows the saved title.
  - **Re-renders:** an open editor stays open if another row is toggled or deleted.
- `app/test.js`: five new tests for valid and trimmed updates, rejection of invalid titles, completion-only updates, other todos staying unchanged, and the 404 case.

**Commands run:** `npm test` from `app/` gave 14 tests, 14 passed, 0 failed. That is the 9 existing tests plus the 5 new ones.

I couldn't use the shell to apply file edits, so I made them with the edit tools. Nothing was committed or pushed.
